# 長照人員教育訓練積分查詢與效期管理系統 (v5.0 雲端整合版)

本專案由原 Python Tkinter GUI 應用程式完整轉移至網頁版 (React + TS + Vite + Firebase)，並整合了多租戶機構權限管理與自動化小卡起訖日儲存功能。

---

## 🛠️ 技術棧 (Technology Stack)
* **前端核心**：React (Vite) + TypeScript
* **樣式設計**：Vanilla CSS (極簡暗黑毛玻璃 Glassmorphism，支援高度互動 hover 動畫與表單驗證)
* **資料解析**：SheetJS (`xlsx`)，支援在瀏覽器端本機直接解析衛福部匯出之 Excel
* **後端服務**：Firebase (Authentication 驗證 + Cloud Firestore 資料庫)
* **版本控管**：Git (已內置安全過濾機制，自動排除私密憑證 `.env` 與上傳的學員資料 `.xlsx`/`.csv`)

## 📝 核心積分計算邏輯與規則 (Business Rules)
本系統之核心統計演算法定義於 [`src/calculator.ts`](file:///c:/Users/MAC/Desktop/ltcp_manager/src/calculator.ts)，整合了以下法規邏輯：
1. **換證總分要求**：須達 **120 分**。
2. **專業品質、倫理、法規 (QER)**：最低要求 **24 分**，且採計上限為 **36 分**。
3. **線上課程 (Online) 上限判定**：
   * 依據學員小卡**生效日期**判定：
      * 生效日期在 **民國 112 年 10 月 12 日前 (含)**：線上課程採計上限為 **60 分**。
      * 生效日期在 **民國 112 年 10 月 12 日後** 至 **民國 115 年 06 月 30 日前 (含)**：線上課程採計上限為 **40 分**。
      * 生效日期在 **民國 115 年 07 月 01 日後 (含)**：線上課程採計上限為 **80 分**。
4. **四大核心課程 (消防、緊急、感控、性別)**：
   * 每科積分皆須 **$\ge 1$ 分**。
   * 四科總分累計須 **$\ge 10$ 分**。
5. **多元與原住民文化課程**：
   * **舊制**（民國 113/06/02 前）：「原住民族與多元族群文化敏感度及能力」為單一合併類別，**認列上限 2 分 —— 超過 2 分的部分不予採計**。
     * 超額的分數會從它原本落入的**屬性桶**扣除（`applyCulturalOldCap()`），不是從最終總分減掉。原因有兩個：
       1. **避免與 QER 36 分上限重複扣除**。若某人的 QER 原始積分本來就遠超 36 分，超額部分早已被 36 分上限丟棄，再從總分減一次等於罰兩次。實測案例：某員舊制文化 16.8 分（超額 14.8），QER 原始 87.16 分，套用上限後總分不變（正確）；另一員舊制文化 8.26 分（超額 6.26），QER 僅 25.7 分在上限之下，總分足額下降 6.26（正確）。
       2. **QER 24 分下限的判定也要用扣除後的分數**。不予採計的積分不該拿來湊下限。
     * 扣除順序為「先扣網路、後扣實體」，與 QER 超額處理一致，對學員較有利（網路積分另外還受線上採計上限限制，先扣網路的淨損失較小）。
     * 需要課程明細才能知道要從哪個屬性桶扣除。`PointsData.culturalOldRecords` 由 Excel 解析填入；從雲端小卡載入時為 `undefined`，此時**無法自動扣除**，會在「注意」欄位標明「總分可能高估」，報表的「舊制文化超上限未採計」欄位顯示「無明細無法扣除」。
   * **新制**（民國 113/06/03 起）：拆成「原住民族文化」與「多元族群文化」兩科，為**逐年**規定 —— **每個證書年度各需 $\ge 1$ 分**。
     * 系統會依生效日與到期日切出各個證書年度（第 i 年 = 生效日 + (i-1) 年 ~ 生效日 + i 年 - 1 天，最後一年以到期日為界），只對**起始日在 113/06/03 當天或之後**的年度進行檢核（該年度開始時規定尚未生效者不追溯要求）。
     * **各年度會依評估基準日標記三種時間狀態，判定方式不同**：
       * `past`（已結束）：兩科任一不足即為**已逾期未達標**，無法補回，會影響 `isCulturalYearlyMet`。
       * `current`（進行中）：不足只標為**本年度待補**，提醒於年度結束前補課，不算失敗。
       * `future`（未開始）：完全不列為缺失。未發生的年度不可能不合格。
     * `calculatePoints(pointsData, courses, asOf)` 的第三個參數為評估基準日，預設為今天。**測試務必傳入固定日期**，否則結果會隨真實時間漂移。
     * 逐年檢核需要課程明細。從 Excel 匯入時可逐年驗證；從雲端小卡載入（無課程明細）時 `culturalNewRecords` 為 `undefined`，會退回「整個週期至少 1 分」的彙總檢核，並在報表中明確標示「無課程明細，無法逐年驗證」。
     * 結果會寫入報表的「新制文化逐年檢核」欄位，格式為「已逾期未達標：…｜本年度待補：…」。
6. **同步線上課程實體認定**：`01-3 視訊課程` 預設歸類為**實體課程**以利積分統計。
7. **「課程屬性」與「課程類別」是兩個正交維度**（對應衛福部匯出檔的兩個欄位）：
   * **課程屬性**（專業課程／專業品質／專業倫理／專業法規）決定積分**如何計入 120 分總分**。
   * **課程類別**（消防安全／緊急應變／感染管制／性別敏感度／文化課程）決定積分**滿足哪些獨立科目要求**。
   * 同一門課會同時落在兩個維度。四大核心與文化課程的積分**不會另外加到總分上**，它們是同一批積分依類別所做的交叉檢視。
   * 唯一例外是**舊制文化課程的 2 分認列上限**：那是依「課程類別」判定、但會實際從屬性桶扣減總分的規則（見規則 5）。
   * 實務影響：一門「感染管制」課程若屬性為「專業品質」，其積分會計入 QER 桶並受 36 分採計上限約束。這是正確行為，非缺陷。

## 📅 效期雙向自動計算邏輯
為了減輕使用者手動計算負擔，表格欄位具備雙向推算：
* **生效日期 $\rightarrow$ 到期日**：`生效日期 + 6 年 - 1 天`（例如：`112/09/01` $\rightarrow$ `118/08/31`）。
* **到期日 $\rightarrow$ 生效日期 (回推)**：`到期日 + 1 天 - 6 年`（例如：`118/08/31` $\rightarrow$ `112/09/01`）。

## 🔒 角色權限管理 (RBAC) & 資料庫架構
系統區分兩種登入角色，資料存放於 Firestore 中以確保多租戶資料完全隔離：

### 1. 資料庫結構 (Firestore Schema)
* **`users/{uid}`** (用戶基本檔)：
  ```json
  {
    "email": "string",
    "name": "string (機構名稱)",
    "orgId": "string (機構專屬ID)",
    "role": "user | admin"
  }
  ```
* **`organizations/{orgId}/student_cards/{studentId}`** (學員效期儲存庫)：
  ```json
  {
    "name": "string (姓名)",
    "effectiveDate": "string (生效日期, 如 112/09/01)",
    "expiryDate": "string (到期日, 如 118/08/31)",
    "updatedAt": "string (ISO timestamp)"
  }
  ```

### 2. 角色權限定義
* **一般機構用戶 (`role === 'user'`)**
  * 系統預設註冊角色。
  * 僅能 CRUD 本身機構 (`orgId`) 的學員小卡資料，無法看到超級管理員控制面板。
* **超級管理員 (`role === 'admin'`)**
  * 須由管理員在 Firebase Console 中，手動將該 `users/{uid}` 文件中的 `role` 欄位設為 `"admin"`。
  * 登入後會載入「👑 超級管理員控制面板」，可以切換並 CRUD 系統中所有註冊機構的學員資料。

## ⚡ Mock 本地測試模式 (LocalStorage Fallback)
若未配置環境變數，系統會自動切換為本地 Mock 模式以利單機測試。此模式預設了兩組測試帳密：
* **一般用戶帳密**：
  * 帳號：`test@example.com`
  * 密碼：`password`
* **超級管理員帳密**：
  * 帳號：`admin@example.com`
  * 密碼：`adminpassword`
* **忘記密碼模擬**：Mock 模式下點擊忘記密碼，系統會直接在瀏覽器彈出視窗（`alert`）中模擬出密碼重設網址。

## 🚀 環境變數與連線設定 (`.env`)
當準備連接真實的 Firebase 服務時，請在專案根目錄下建立 [`.env`](file:///c:/Users/MAC/Desktop/ltcp_manager/.env) 檔案並填寫：
```env
VITE_FIREBASE_API_KEY=你的_API_Key
VITE_FIREBASE_AUTH_DOMAIN=你的_Auth_Domain
VITE_FIREBASE_PROJECT_ID=你的_Project_Id
VITE_FIREBASE_STORAGE_BUCKET=your-bucket.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=你的_Sender_Id
VITE_FIREBASE_APP_ID=你的_App_Id
```
*(注意：修改 `.env` 後需要重啟開發伺服器才會生效。)*

同時請在你的 Firebase Console 啟用 **Firestore Database (default)**，並在 **Authentication** -> **Sign-in method** 中啟用 **Email/Password** 登入。
安全規則請直接參考並套用專案中的 [`firestore.rules`](file:///c:/Users/MAC/Desktop/ltcp_manager/firestore.rules)。
